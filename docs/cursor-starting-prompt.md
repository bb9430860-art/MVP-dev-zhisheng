====================
四、最高优先级业务规则
====================

以下规则必须严格遵守：

1. 上传潜在客户不立即发奖励。
   上传只计入每日客户上新任务。
   只有客户被认领并转为意向客户后，原始上传人才获得线索贡献奖励。

2. 手机号必须唯一。
   重复手机号禁止上传，因此 MVP 不需要“重复线索”状态。

3. 领取不触发冷却。
   领取只是暂时占用客户。
   只有填写联系记录后，才根据联系结果进入冷却、意向、无效或不再联系。

4. 已领取必须显示领取人。
   公海客户被业务员领取后，状态显示“已领取”，并展示领取人、领取时间、首次联系截止时间。

5. 必须防止恶意占坑。
   要限制：
   - 每日领取上限
   - 同时持有未联系客户上限
   - 领取后必须限时联系
   - 超时未联系自动释放并扣贡献值

6. 最低要求应该是“有效联系目标”，不是单纯最低领取数。
   领取没有价值，真实联系才有价值。

7. 贡献值必须有流水。
   不能只改账户余额，所有加减分必须形成 contribution_transaction。

8. 不做工资系统。
   系统展示贡献值和预计奖励，不展示员工基本工资、实际工资条、社保、个人薪资明细。

9. 订单与生产分离。
   你负责订单和产品/点位的创建与描述，Codex 生产线负责产品/点位后续生产配置与执行。

10. 订单字段和产品/点位字段必须支持动态配置。
    这是非标项目的基础能力，不能做成完全写死表单。

====================
五、客户公海状态机
====================

你必须按以下状态机设计：

1. 可领取
   - 公海中的潜在客户，业务员可以领取。

2. 已领取
   - 业务员领取后进入。
   - 显示领取人、领取时间、首次联系截止时间。
   - 领取后不进入冷却。

3. 冷却中
   - 业务员填写联系记录后，如果结果是未接通、暂不需要等，则进入冷却中。
   - 冷却期默认 7 天。
   - 冷却期内其他业务员不能领取。
   - 到期后回到可领取。

4. 意向客户
   - 联系结果显示客户有明确需求。
   - 该客户归当前业务员跟进。
   - 原始上传人获得线索贡献奖励。

5. 正式客户
   - 意向客户转为正式客户档案。

6. 已成单
   - 正式客户产生订单并成交。
   - 成交人和原始上传人获得对应奖励。

7. 已无效
   - 空号、错号、非目标客户等。

8. 不再联系
   - 客户明确拒绝或管理员标记为不再联系。

====================
六、贡献值规则
====================

MVP 中至少支持以下贡献值事件：

1. 上传合格潜在客户
   - 只计入每日客户上新任务
   - 不直接发奖励

2. 上传客户转意向
   - 原始上传人获得贡献值

3. 认领客户转意向
   - 认领并转化的人获得贡献值

4. 客户成交
   - 成交人获得贡献值
   - 原始上传人也获得贡献值

5. 领取超时未联系
   - 领取人扣贡献值
   - 客户自动释放回公海

6. 管理员手动奖励/扣减
   - 必须填写原因
   - 必须记录操作人和时间

7. 生产线/考勤线贡献事件
   - Codex 生产线可能提交 ATTENDANCE_LATE、PRODUCTION_CHECKIN 等事件
   - 你负责统一处理事件并写入贡献值流水

3. 库存预警信息
